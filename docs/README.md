# dsh-site-bridge

Мост между DeepSeek Harness и **вашим обычным браузером**: расширение живёт в вашем профиле
Chrome/Edge, работает с вашими куками и не выносит авторизацию никуда — ни в модель, ни на диск.

Задача, под которую он сделан: снять с сайта разметку и его BFF API, а потом написать расширение,
которое встраивается в страницы этого сайта. Пакет снимка — это файлы в рабочем пространстве,
по которым агент пишет код, а не «магия» внутри браузера.

## Что даёт агенту

| Инструмент | Что делает |
|---|---|
| `site_status` | состояние моста, подключённая вкладка, путь к файлу с токеном для popup |
| `site_tabs` | список вкладок, выбор той, с которой работаем |
| `site_capture` | снимок → пакет в рабочем пространстве: `dom.html`, `dom.json`, `styles.json`, `selectors.md`, `network.jsonl`, `api.md`, `meta.json`, `README.md`, опционально `screenshot.png` |
| `site_network` | `start` / `stop` / `list` / `get` / `clear` — xhr/fetch с заголовками и телами |
| `site_act` | клик, hover, ввод (`type`), заполнение (`fill`), `select`, `press`, `scroll`, `upload`, `goto`, `reload`, `wait`, `exists`, `eval`, `screenshot` |
| `site_cursor` | виртуальный курсор: подвинуть в координаты и кликнуть настоящим событием мыши |
| `site_shot` | скриншот вкладки в файл (`captures/shots/*.png`): видимая часть или вся страница. Работает и для фоновой вкладки, base64 в контекст не попадает |
| `site_inject` | выполнить ваш скрипт и/или CSS в странице — проверить, что расширение встраивается |

Ввод идёт через CDP (`Input.dispatchMouseEvent`, `Input.insertText`, `DOM.setFileInputFiles`),
поэтому это **доверенные события**: страница не отличает их от действий человека. Это же лечит
кнопки, которые не реагируют на программный `element.click()`.

## Установка

Две половины: плагин в DSH и расширение в браузере.

### 1. Плагин в профиль DSH

```powershell
# из папки site-bridge
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install.ps1
```

Скрипт ставит плагин в профиль `desktop` и копирует расширение в стабильную папку
`%USERPROFILE%\.dsh\site-bridge\extension`. Либо вручную:

```powershell
dsh plugin --profile desktop add "C:\Users\k4\Documents\deepseek-harness\default-workspace\site-bridge"
```

Не забудьте добавить `dsh-site-bridge` в `dsh.profile.bundles` профиля
(`%USERPROFILE%\.dsh\profiles\desktop\package.json`) — без этого плагин установлен, но не подключён.

Затем перезапустите DSH (host-часть плагина загружается при старте профиля).

Проверка: в новом чате попросите `site_status` — должен вернуться порт и путь к файлу с токеном.

### 2. Расширение в браузере

1. `chrome://extensions` (или `edge://extensions`) → включите **Режим разработчика**.
2. **Загрузить распакованное** → выберите папку `...\site-bridge\extension`.
3. Нажмите иконку расширения → вставьте порт и токен из файла, который печатает `site_status`
   (по умолчанию `%USERPROFILE%\.dsh\site-bridge\bridge.json`).
4. Кнопка **«Подключить вкладку»** — привязывает текущую вкладку к DSH.

Chrome покажет плашку «Началась отладка этого браузера» — это ожидаемо: именно через CDP
работают доверенный ввод и запись тел запросов. Плашка исчезает после «Отключить».

> Chrome 137+ игнорирует флаг `--load-extension` при запуске. Для ручной загрузки через
> `chrome://extensions` это неважно; для автоматизации используется `Extensions.loadUnpacked` по CDP
> (так работает e2e-тест).

## Рабочий цикл

1. `site_tabs` → выбрать вкладку с нужной страницей.
2. `site_capture` → получить пакет.
3. Прочитать `selectors.md` (якоря), `styles.json` (токены темы), `api.md` (контракты BFF).
4. Написать расширение в своём репозитории.
5. `site_inject` — проверить, что панель вставляется, якорь находится, а вызов BFF проходит
   с куками браузера.

## Безопасность

- **Авторизация не покидает браузер.** Расширение не читает куки и токены само: запросы делает
  страница, браузер прикладывает куки. Мост видит их в трафике, но:
  - значения заголовков `cookie`, `authorization`, `x-csrf-token`, `x-api-key`, `set-cookie` и
    подобных заменяются на `«redacted»` **при приёме**, в памяти моста уже нет оригинала;
  - секретные поля JSON/форм (`token`, `password`, `csrf`, `session`, …) заменяются так же;
  - секретные query-параметры маскируются в URL.
- **Ничего авторизационного не пишется на диск.** `network.jsonl` и `api.md` содержат только
  уже отредактированные данные. Имена заголовков сохраняются — по ним видно, что эндпоинту нужен
  CSRF-заголовок, но само значение в артефакт не попадает.
- **Мост слушает только loopback** (`127.0.0.1`) и требует токен в каждом запросе.
  Токен — 32 байта случайности, лежит в `bridge.json` с правами вашего пользователя.
  `site_status` по умолчанию печатает только путь к файлу, не сам токен (чтобы он не ушёл в модель).
- **Риск, который остаётся:** заголовки и тела запросов всё равно проходят через процесс DSH
  в памяти. Если сайт кладёт токен в нестандартное поле — редакция его не узнает.
  Считайте пакет снимка чувствительным, как и любой дамп трафика.

## Ограничения

Четыре принципиальных ограничения разобраны отдельно — что именно ломается, где в коде причина
и как это снять: [limitations.md](limitations.md).

- **iframe не обходится**: снимок и действия идут по `document` верхнего фрейма.
- **shadow DOM обходится частично**: открытые корни видны, но селекторы для них не разрешаются;
  закрытые не видны совсем.
- **Тело ответа ≤ 400 000 символов**; base64-тела не сохраняются, только пометка.
- **Один таб на сессию**: новая привязка отключает предыдущую.

Остальное:

- Снимаются только **API-вызовы сайта**: `xhr`/`fetch` того же хоста, того же домена второго уровня
  или сторонние ответы с JSON. Телеметрия и антивирусные плагины, которые отправляют дамп HTML
  страницы на свой сервер, отфильтровываются — иначе исходник страницы (с инлайн-токенами)
  попадал бы в пакет.
- Запись стартует «сейчас»: запросы, случившиеся до `net.start`, в пакет не попадут.
  Если запись уже идёт, `site_capture` включает в пакет всё, что записано с момента `net.start`
  (сценарий «включил запись → нажал кнопку → снял пакет»); сбросить — `site_network {action:"clear"}`.
- Пакет по умолчанию пишется в `captures/` рабочей папки сессии; `dir` переопределяет.
- `upload` принимает абсолютные пути на машине, где работает DSH.
- Закрытие вкладки/перезапуск браузера отвязывает debugger — нужно снова «Подключить вкладку».
- MV3 service worker может быть выгружен Chrome; мост переподключится сам, но незавершённая
  команда отвалится по таймауту.
- **Правки host-части (папка `lib/`) применяются только после перезапуска DSH**: плагин
  загружается при старте профиля. Правки расширения подхватываются кнопкой «Обновить»
  на `chrome://extensions`.

## Тесты

```powershell
cd site-bridge

# быстрые, без браузера
node test\redact.test.mjs
node test\bridge.test.mjs
node test\artifacts.test.mjs
node test\plugin.test.mjs

# end-to-end в реальном Chrome (поднимает свой профиль в .e2e-profile)
node test\e2e.mjs

# слой инструментов + реальный Chrome (проверяет lib/index.js целиком)
node test\tools-chrome.mjs
```

`e2e.mjs` поднимает страницу с рабочим BFF-вызовом, загружает расширение через
`Extensions.loadUnpacked`, привязывает вкладку и проверяет: доверенный ввод, запись запроса
с телом и заголовками, редакцию cookie/CSRF, снимок разметки с селекторами, виртуальный курсор
по координатам, загрузку файла, инъекцию скрипта и скриншот. 31 проверка.

`tools-chrome.mjs` делает то же через сами инструменты (`site_status` → `site_network` →
`site_act` → `site_capture` → `site_cursor` → `site_inject`) и дополнительно проверяет, что пакет
лежит в воркспейсе сессии, что в него попадает трафик, записанный до `site_capture`, и что
значения cookie/CSRF/токенов не встречаются в файлах пакета. 19 проверок.

## Структура

```
lib/index.js      инструменты DSH
lib/bridge.js     loopback-мост: long-poll, токен, очередь команд, состояние
lib/redact.js     редакция авторизации
lib/artifacts.js  раскладка пакета снимка
extension/        MV3: service worker (CDP), popup, иконки
test/             юнит-, интеграционные и e2e-тесты
```

## Иконка

Знак: **страница браузера с китом DSH**. Белая плитка (страница) на синем градиенте DeepSeek,
сверху полоса браузера с точками, внутри — кит. Инверсия выбрана осознанно: белая плитка держит
контраст и на светлой, и на тёмной панели Chrome, а кит — узнаваемая отсылка к DSH/DeepSeek.

Источник — SVG, PNG собираются из него тем же Chrome, в котором работает расширение:

```
extension/icon.svg         детальная версия: три точки в полосе, глаз кита (48/128)
extension/icon-small.svg   оптический вариант: одна точка, без глаза, толще штрихи (16/32)
extension/icons/*.png      16/32/48/128, подключены в manifest (icons + action.default_icon)
```

Пересобрать после правки SVG:

```powershell
node tools/make-icons.mjs                                    # растеризация в extension/icons
node tools/preview-icon.mjs extension/icons/icon-16.png 8    # посмотреть 16px увеличенным
node tools/preview-sheet.mjs extension/icon.svg extension/icon-small.svg   # сравнить варианты
```

MV3 не принимает SVG в манифесте, поэтому SVG остаётся исходником, а PNG — артефактом сборки.
Логотип в шапке popup берётся из `extension/icons/icon-128.png`.
